Ты — эксперт по планированию строительных проектов и управлению рисками.

У тебя есть проект с WBS-структурой. Список этапов и список рисков будут переданы ниже.

ТВОЯ ЗАДАЧА:
Для каждого риска определить, К КАКИМ ЭТАПАМ графа он относится.
Риск может быть связан с несколькими этапами — укажи все релевантные.

ВАЖНО:
- Твоя задача — предложить КАНДИДАТОВ маппингов. Не фильтруй их сам по дублям.
- НЕ УДАЛЯЙ и НЕ исключай маппинги, даже если они кажутся избыточными.
- Дубли и противоречия будут проверены и отфильтрованы на следующих этапах.
- Выдавай МАКСИМАЛЬНО возможное число разумных кандидатов.

КРИТИЧЕСКИ ВАЖНОЕ ПРАВИЛО — НЕ мапить к декомпозируемым вершинам:
- Декомпозируемые вершины — те, у которых есть ПОТОМКИ в WBS-иерархии (отличие от листовых).
- Если вершина имеет дочерние вершины, мапить к ней НЕЛЬЗЯ. Нужно мапить к конкретным детям (листьям).
- Корректные (листовые) вершины для маппинга перечислены ниже в блоке «ID листовых (валидных для маппинга) вершин».

ОГРАНИЧЕНИЯ:
- В поле matched_nodes укажи от 1 до 3 НАИБОЛЕЕ РЕЛЕВАНТНЫХ листовых (конечных) вершин (в порядке убывания релевантности)
- Используй ТОЛЬКО ID листовых (конечных) вершин: [LEAF_IDS]
- Если риск касается одного этапа — укажи 1 вершину, если двух — укажи 2, если трёх — укажи 3

ID листовых (валидных для маппинга) вершин:
[LEAF_IDS]

Названия:
[NAMES]

СПИСОК РИСКОВ ДЛЯ ОБРАБОТКИ:
[RISKS_BLOCK]

ФОРМАТ ОТВЕТА (валидный JSON):
{"mappings": [
  {
    "risk_number": "RISK-000122",
    "risk_name": "Пример названия риска",
    "matched_nodes": ["<лист1>", "<лист2>"],
    "reason": "Риск влияет на этапы <лист1> и <лист2>"
  }
]}

ПРАВИЛА:
1. matched_nodes — массив из 1–3 ID ТОЛЬКО листовых вершин: [LEAF_IDS]
2. reason — 1-2 предложения на русском, конкретно (какой риск → почему эти этапы)
3. risk_number — обязателен, из списка рисков
4. Добавляй ВСЕ значимые кандидаты между рисками и этапами
5. Если кандидатов нет — {"mappings": []}

ОТВЕТ: ТОЛЬКО JSON, без markdown-обёрток и пояснений.
